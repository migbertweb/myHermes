## 📋 Resumen Ejecutivo

**Honcho** es una plataforma de memoria para agentes de IA con **razonamiento automático (dialectic reasoning)**. En lugar de simple almacenamiento clave-valor, Honcho analiza las conversaciones en segundo plano y construye un modelo del usuario: preferencias, estilo de comunicación, metas y patrones. La mejor noticia: **Hermes Agent ya tiene soporte nativo para Honcho** como proveedor de memoria externo, y está instalado en tu sistema pero inactivo.

## 1️⃣ Cómo hacer Self-Hosted Honcho en tu servidor (192.168.1.8)

### Stack necesario
| Componente | Función |
|---|---|
| **PostgreSQL + pgvector** | Base de datos principal con vectores |
| **Redis** | Caché y cola de procesamiento |
| **Honcho API (FastAPI)** | Servidor REST |
| **Deriver (worker)** | Procesamiento asíncrono en segundo plano |
| **LLM API Key** | Para razonamiento (OpenAI, Anthropic o Gemini) |

### Hardware mínimo
El README no especifica requisitos exactos, pero al ser FastAPI + PostgreSQL con pgvector, **un VPS de 2GB RAM y 2 CPUs (tipo Hetzner CX22/CX32) basta** para uso personal. Los workers de deriver son los que más consumen.

### Pasos (Docker — RECOMENDADO)

```bash
# 1. Clonar el repo y preparar
git clone https://github.com/plastic-labs/honcho.git
cd honcho
cp docker-compose.yml.example docker-compose.yml
cp .env.template .env

# 2. Configurar .env — REQUERIDO: al menos un LLM API key
LLM_GEMINI_API_KEY=...   # Para deriver/summary/dialectic minimal/low
LLM_OPENAI_API_KEY=...   # Para embeddings (text-embedding-3-small)

# 3. Iniciar
docker compose up -d --build
```

Esto levanta: Honcho API en `localhost:8000`, PostgreSQL en `5432`, Redis en `6379`.

### Autenticación (opcional pero recomendado)
1. Generar JWT secret: `python scripts/generate_jwt_secret.py`
2. Setear en `.env`: `AUTH_USE_AUTH=true` y `AUTH_JWT_SECRET=...`
3. Generar token: `python scripts/generate_jwt.py --admin --expires 365d`
4. El token se usa como `apiKey` en la configuración de Hermes

### Sin Docker (alternativa con uv)
```bash
uv sync
cp docker-compose.yml.example docker-compose.yml
docker compose up -d database   # Solo Postgres + Redis con Docker
uv run alembic upgrade head
uv run fastapi dev src/main.py       # Terminal 1: API
uv run python -m src.deriver        # Terminal 2: worker
```

### Despliegue en tu servidor
Una vez funcionando localmente, en tu servidor (192.168.1.8):
- Ajusta los puertos/paths según tu infraestructura
- Opcional: poner un reverse proxy (nginx/caddy) con TLS/SSL
- El servicio escucha en `http://192.168.1.8:8000` por defecto

Y en `~/.hermes/config.yaml`:

```yaml

  provider: honcho
  memory_enabled: true
```

### Lo que obtienes al activarlo

Honcho expone **5 herramientas** nuevas en Hermes:

| Tool | Qué hace |
|---|---|
| `honcho_profile` | Leer/actualizar peer card (perfil del usuario) |
| `honcho_search` | Búsqueda semántica sobre el contexto |
| `honcho_context` | Contexto completo de sesión (summary + representation + card) |
| `honcho_reasoning` | Respuesta sintetizada por el LLM de Honcho (costo mayor) |
| `honcho_conclude` | Crear/eliminar conclusiones |

Y tres modos de recall (`recallMode`):
- **hybrid** (default) — contexto auto-inyectado + herramientas disponibles
- **context** — solo auto-inyección, sin herramientas
- **tools** — solo herramientas, sin auto-inyección

## 3️⃣ ¿Vale la pena? Honcho vs Memoria Nativa de Hermes

### Comparativa

| Capacidad | Memoria Nativa (MEMORY.md/USER.md) | Honcho |
|---|---|---|
| Persistencia entre sesiones | ✅ Archivos markdown | ✅ Servidor con API |
| Perfil de usuario | ⚠️ Curación manual del agente | ✅ Razonamiento dialéctico automático |
| Resumen de sesión | ❌ No | ✅ Contexto por sesión |
| Aislamiento multi-agente | ❌ No | ✅ Perfiles por peer separados |
| Razonamiento (conclusiones) | ❌ No | ✅ Inferencias automáticas en servidor |
| Búsqueda semántica | ✅ FTS5 en sesiones | ✅ Híbrida (BM25 + vectores) |
| Infraestructura | ✅ Sin dependencias | ❌ Requiere servidor (PostgreSQL + Redis + LLM) |
| Costo operativo | ✅ 0 | ⚠️ LLM API keys para razonamiento |
| Privacidad total (self-hosted) | ✅ Sí | ✅ Sí (si self-hosteas) |

### Veredicto

**✅ RECOMENDADO — pero con matices:**

**A favor:**
- Es complementario, no sustitutivo — la memoria nativa de Hermes sigue funcionando mientras Honcho está activo. No pierdes nada.
- El razonamiento dialéctico es un **salto cualitativo**: Honcho no solo guarda, *entiende* patrones del usuario.
- El aislamiento multi-peer permite tener perfiles separados para diferentes contextos (código, personal, etc.)
- Está **totalmente integrado** en Hermes — `hermes memory setup honcho` y listo.
- Self-hosted = privacidad total, sin depender de servicios cloud externos (el objetivo de Migbert ✅).

**En contra / a considerar:**
- **Requiere mantener infraestructura**: PostgreSQL + Redis + worker de deriver corriendo 24/7 en tu servidor.
- **Necesita LLM API keys** para funcionar — aunque self-hostees Honcho, el razonamiento necesita un modelo externo (OpenAI, Anthropic o Gemini). Esto significa que no es 100% offline/local.
- **Costo de operación**: cada interacción del deriver consume tokens del LLM que configures. No es gratis.
- **Complejidad adicional**: un punto más de fallo en la cadena.
- **Licencia AGPL-3.0**: si lo modificas y redistribuyes, cuidado.

### Alternativas menos complejas

Si mantener PostgreSQL + Redis + worker te parece mucho, considera:

| Alternativa | Self-hosted | Razonamiento | Qué ganas |
|---|---|---|---|
| **Holographic** ✅ | ✅ Local (SQLite + vectores) | ❌ No | Búsqueda semántica local, sin servidores |
| **Hindsight** | ✅ Local | ⚠️ Básico | Memoria temporal con resúmenes |
| **OpenViking** | ⚠️ API key | ✅ Sí | Similar pero cloud |
